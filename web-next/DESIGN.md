# open-base デザインシステム

shadcn/ui + Tailwind CSS ベースのデザイン規約。コンポーネントの使い方・トークン・レイアウトパターンを定義する。

## デザイントークン

`globals.css` の CSS 変数で管理。oklch カラースペースを使用。

#### 面の重ね方

サイドバーとコンテンツの境界を色で作る。ライトではコンテンツを一段暗く、ダークでは一段
明るくして、サイドバーと分ける。

| 面                             | トークン       | ライト       |
| ------------------------------ | -------------- | ------------ |
| サイドバー                     | `--sidebar`    | 白           |
| コンテンツ領域                 | `--content`    | ライトグレー |
| カード・入力欄・outline ボタン | `--card`       | 白           |
| 補助的な面・ホバー             | `--muted` ほか | グレー       |

構成ルール:

- コンテンツ領域の背景は `SidebarInset` が `bg-content` で持つ。ページ側で背景を敷かない
- カード・入力欄・バッジ・チェックボックス・空状態の面の色は shadcn の生成物（`components/ui/`）の既定に従う。生成物は手編集せず、面の見え方は theme token（`--card`、`--input`、`--popover` など）だけで調整する
- `--secondary` / `--muted` / `--accent` は `--content` の上に置かれる。差が足りないと面が消えるので、白背景時代より一段濃くしてある

### 間隔（Spacing）

余白と間隔は 2 の冪だけを使う。使ってよい値は `0`、`2`、`4`、`8`、`16`、`32`、`64` と `px` に限る。

対象は `gap-*`、`p-*`（`px` / `py` / `pt` / `pb` / `pl` / `pr` を含む）、`m-*`（同様）、`space-x-*` / `space-y-*` である。`1`、`3`、`5`、`6`、`1.5`、`2.5` のような中間値と、`p-[0.15rem]` のような任意値は使わない。

段階が足りないと感じたときは値を刻まず、入れ子の構造を見直す。要素の間は `gap-2`、関連する要素のまとまりの間は `gap-4`、セクションの間は `gap-8` を基準にする。

`web/components/ui/` の shadcn/ui 生成物はこの規則の対象外とする。生成物は手編集しないため、内部で使う値をこちらの都合で変えない。

## コンポーネント使用規約

`web/components/ui/` の shadcn/ui コンポーネントへ、色やサイズを変える `className` を渡すことを禁止する。対象は色（`bg-*`、`text-{色}`、`border-{色}`）、文字サイズ（`text-xs`〜`text-xl` 等）、箱のサイズ（`size-*`、`h-*`、`w-*`（`w-full` を除く）、`min-w-*`、`max-w-*`、`p-*` 系）、角丸（`rounded-*`）、枠線の有無や太さ（`border`、`border-*`）、影（`shadow-*`）、フォントの太さ（`font-*`）、`tracking-*` である。見た目の変更は `variant` と `size` の props、および theme token（CSS 変数）で表現する。配置と余白（`flex`、`grid`、`gap-*`、`items-*`、`justify-*`、`w-full`、margin 系、`hidden` などの表示切替、`truncate`、揃え）はこの禁止の対象外で、これまでどおり `className` で渡してよい。列幅など個別にサイズを持たせたい場合は、対象コンポーネントを `div` で包み、その `div` 側にサイズ指定の `className` を渡す。

`Button` の `outline` バリアントはこの製品では使わない。セカンダリアクションは `secondary` バリアントに統一する。

### Button

6 バリアント × 8 サイズ。`@base-ui/react` ベース。

#### バリアント

| バリアント    | 見た目                | 用途                                                   |
| ------------- | --------------------- | ------------------------------------------------------ |
| `default`     | 塗りつぶし（primary） | メインの CTA。1画面に1つが理想                         |
| `secondary`   | 薄い背景              | セカンダリアクション（キャンセル、フィルタ、補助操作） |
| `ghost`       | 背景なし              | ツールバー、サイドバー内のアクション                   |
| `destructive` | 赤系背景              | 削除、解除など破壊的操作                               |
| `link`        | アンダーライン        | インラインリンク風ボタン                               |

#### サイズ

| サイズ    | 高さ | 用途                             |
| --------- | ---- | -------------------------------- |
| `xs`      | 24px | コンパクトな操作（テーブル内等） |
| `sm`      | 32px | サブアクション                   |
| `default` | 36px | 通常のボタン                     |
| `lg`      | 40px | フォーム送信などの主要アクション |
| `icon`    | 36px | アイコンのみ（正方形）           |
| `icon-xs` | 24px | 小さいアイコンボタン             |
| `icon-sm` | 32px | 中アイコンボタン                 |
| `icon-lg` | 40px | 大アイコンボタン                 |

#### 使い分けルール

- ページ内のメイン CTA は `default` バリアントを1つだけ
- 並列する操作は `secondary`
- 削除は必ず `destructive` + 確認ダイアログ
- テーブル行内は `ghost` + `icon-xs` または `icon-sm`
- Button の中にアイコンを置くときは lucide のアイコンを子要素にし、`data-icon="inline-start"` / `"inline-end"` で位置を示す

### Badge

6 バリアント。ステータス表示に使う。

Badge は行の中で Button や Input と並べない。Badge は高さが小さく、同じ行に Button があると高さが揃わない。テーブル行や、Button・Input と同じ行に置く押せないラベル（アカウントの状態、付与済みロールなど）は `StatusLabel` で表し、押せるもの（剥奪など）は `Button` の submit にする。Badge を残すのは、カウンタ、タグの並び、カードの見出しのように Button と高さを揃える必要がない箇所に限る。

| バリアント    | 用途                 | 例                   |
| ------------- | -------------------- | -------------------- |
| `default`     | アクティブ・完了     | 承認済み、有効       |
| `secondary`   | 中立的なラベル       | 下書き、待機中       |
| `destructive` | エラー・失効         | 却下、無効、期限切れ |
| `outline`     | 情報ラベル           | カテゴリ、タグ       |
| `ghost`       | 控えめなラベル       | 補足情報             |
| `link`        | クリック可能なラベル | フィルタタグ         |

#### ステータスバッジの色マッピング

業務上のステータスと Badge バリアントの対応。この表は Badge のまま残す箇所にだけ当てる。

| ステータス                 | バリアント    | 例                     |
| -------------------------- | ------------- | ---------------------- |
| 承認済み・完了・有効       | `default`     | 申請承認、出勤中       |
| 申請中・レビュー中・処理中 | `secondary`   | 休暇申請中、経費申請中 |
| 却下・失効・エラー         | `destructive` | 申請却下、期限切れ     |
| 下書き・未提出             | `outline`     | 下書き保存             |

### StatusLabel

押せない状態表示のコンポーネント（`components/status-label.tsx`）。テーブル行や、Button・Input と同じ行に置くラベルに使う。

- 見た目と高さは `buttonVariants` から作るため、同じ size の Button と揃う。既定の size は `sm`（32px）で、`default`（36px）の Button と並ぶときだけ `size="default"` を渡す
- 要素は `span` で、フォーカスを受けず、支援技術へボタンとして伝わらない。hover や押下の見た目の変化も出さない
- 押せない状態表示を `Button` で描かない。`<button>` はスクリーンリーダーに「ボタン」と読み上げられ、押せると誤解させる
- `className` は受け取らない。見た目は `variant` と `size` だけで変える

```tsx
<TableCell>
  <StatusLabel>承認待ち</StatusLabel>
</TableCell>
```

#### StatusLabel の色マッピング

`StatusLabel` のステータスは、上の Badge の表を当てず次の 2 値に畳む。

- 却下・失効・エラー（申請却下、期限切れ、不足）は `destructive`
- それ以外のすべて（承認済み、申請中、下書き）は `secondary`（既定）

`default` は 1 画面に 1 つのメイン CTA と同じ塗りになるため、ステータス表示には使わない。`outline` も使わない（Button の `outline` は `secondary` に統一する規則がある）。

状態の区別は色ではなくラベルの文言で示す。色数を増やしたくなったら、その情報がラベルに書かれているかを先に確かめる。

### リンク

押せることが一目で分かるよう、前進するリンクには `ChevronRight` を添える。アイコンは
`text-muted-foreground/40` で薄く置き、文字より目立たせない。

| 種類           | コンポーネント | アイコンの位置           |
| -------------- | -------------- | ------------------------ |
| カードリンク   | `CardLink`     | カードの右下（絶対配置） |
| テキストリンク | `TextLink`     | 文末（インライン）       |

構成ルール:

- カード全体をリンクにするときは `CardLink` を使う。`Card` と `Link` を直接組み合わせない
- 「〇〇を開く」のような文章型・CTA 型のリンクは `TextLink` を使う
- 一覧テーブルの識別子リンク（従業員名・申請番号など）には `TextLink` を使わない。行ごとに記号が並んで一覧が読みにくくなるため、素の `Link` のままにする
- 「一覧へ戻る」のような後退する導線には `ChevronRight` を付けない。`BackButton`（`ArrowLeft`）を使う
- 監査・証跡画面では `CardLink` / `TextLink` にも `prefetch={false}` を渡す

### カーソル

押せる・選べる要素は必ず `cursor: pointer` にする。Tailwind v4 で `button` の既定が
`default` に変わったため、`app/globals.css` の `@layer base` でまとめて指定している。

- 新しいプリミティブを追加するときは、`role` が base 層の列挙に含まれるか確認する
- 含まれない場合は base 層に追記する。コンポーネント側で個別に当てない
- `cursor-default` を明示しない。base 層の指定に勝ってしまう
- 無効時は `disabled:cursor-not-allowed` か `disabled:pointer-events-none` のどちらかを当てる

## レイアウトパターン

### 一覧ページ

```
PageHeader（タイトル + アクションボタン）
├── フィルタ / 検索（任意）
├── Table
│   ├── SortableTableHead
│   └── テーブル行
└── TablePagination
```

構成ルール:

- PageHeader の `actions` にメインの CTA（新規作成等）を配置
- テーブルは `Table` コンポーネントを使う
- ソート可能なカラムは `SortableTableHead` で統一
- 0 件時は `EmptyState` を表示
- ページネーションは `TablePagination` で統一

#### 監査・証跡画面の例外

- read 自体が監査イベントを生む導線は、viewport や hover だけで記録を増やさないよう、すべての `Link` に `prefetch={false}` を指定する
- opaque cursor は値や方向を解釈せず、`TablePagination` ではなく前後 cursor 専用のナビゲーションを使う
- CSV は Server Action や RSC の payload に載せず、`Cache-Control: no-store` の Route Handler から API response body を stream する
- IP や証跡 JSON は専用 permission で保護した詳細画面にだけ表示し、JSON は項目別に初期折り畳みとする

### 詳細ページ

```
PageHeader（タイトル + 戻るボタン + アクションボタン）
├── Card
│   ├── CardHeader
│   └── CardContent
│       └── DetailField のグリッド
└── 関連データセクション（任意）
```

構成ルール:

- `BackButton` で前のページに戻れるようにする
- 詳細データは `DetailField`（dt/dd）で表示
- 編集・削除は PageHeader の actions に配置
- ローディング中は構造化スケルトンを表示

### 新規作成 / 編集フォーム

```
PageHeader（タイトル + 戻るボタン）
├── Card
│   ├── CardHeader
│   └── CardContent
│       └── フォームフィールド
└── フッター（送信ボタン + キャンセル）
```

構成ルール:

- フォームの送信ボタンは `default` バリアント
- キャンセルは `secondary` バリアント
- バリデーションエラーは各フィールド直下に表示
- 送信中はボタンに `Loader2Icon` のスピナーを表示

## 共通コンポーネント

### PageHeader

全ページの上部に配置。タイトルと操作ボタンを含む。

```tsx
<PageHeader
  title="従業員一覧"
  actions={
    <Button>
      <Plus /> 新規登録
    </Button>
  }
/>
```

### EmptyState

データが 0 件の場合に表示。アイコン + メッセージ + CTA を含む。

```tsx
<EmptyState
  icon={Users}
  title="従業員がいません"
  description="最初の従業員を登録しましょう"
  action={<Button>新規登録</Button>}
/>
```

### ListSkeleton

一覧ページのローディング表示。テーブル形式のスケルトン。

### FetchError

データ取得エラー時の表示。再読み込みボタン付き。

## レスポンシブ対応

### ブレークポイント

Tailwind のデフォルトブレークポイントを使用。

| プレフィックス | 幅     |
| -------------- | ------ |
| `sm`           | 640px  |
| `md`           | 768px  |
| `lg`           | 1024px |
| `xl`           | 1280px |

### レスポンシブルール

- モバイル（`< sm`）: サイドバーは Sheet で開閉。テーブルは横スクロール
- タブレット（`sm` 〜 `lg`）: サイドバーは折りたたみ可能
- デスクトップ（`> lg`）: サイドバーは常時表示

## ダークモード

`ThemeProvider` で管理。`system` / `light` / `dark` の3モード。

### 注意事項

- カスタムカラー（`bg-destructive/10` 等の透過度）はダークモードで別途確認が必要
- `border-border` と `bg-input` はダークモードで oklch alpha を使用
- チャートカラーはライト・ダーク共通

## アクセシビリティ

- フォーカス管理: `focus-visible:border-ring focus-visible:ring-[3px]` で統一
- aria 属性: `aria-invalid` でエラー状態のスタイルを自動適用
- カラーコントラスト: WCAG AA 基準（4.5:1）を目標
- キーボード操作: 全インタラクティブ要素がキーボードで操作可能であること
