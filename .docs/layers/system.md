# System

## 実装を確認した機能

- 主体、アカウント、Identity、ロールと権限の紐付け。
- パスワード、パスキー、OIDCのサインイン設定。ブラウザ、CLI、機械のセッション、資格情報の発行・回復、再認証。
- 手続きと案件、提案の版、作業の受領・差戻し・引き継ぎ・承認、実行許可。
- 監査イベントと開示方針、添付の保全・解放、保存記録と証拠の参照。
- 通知、バッチ、外部接続、受信・配信、照合、処理失敗の再投入、運用診断。

## 網羅性と保守リスク

共通機構としては、操作の認可から判断、記録、失敗後の再処理まで入口がある。業務データの内容や会社上の資格は利用側から受け取る。承認済みの内容が後から変わると判断の意味が崩れるため、対象の版と実行許可を結び付ける。

- 認証・認可は高リスク。失効済みの資格情報、権限変更直後のセッション、回復時の旧資格情報を検証する。
- 判断・実行は高リスク。古い版への承認、二重実行、引き継ぎ中の競合を検証し、誰が誰の権限で判断したかを再構成できるようにする。
- 監査・添付・配信は、閲覧範囲と保全・削除の整合が必要。再配信で業務処理を重複させない。機密の本文を通知や監査ログへ必要以上に複製しない。

実装の入口は[ルート登録](../../web/src/contexts/system/interface/route-manifest.ts)。個人データの取扱いでは、担当者と対象データを絞るアクセス制御が基準となる。 [個人情報保護委員会の通則編](https://www.ppc.go.jp/personalinfo/legal/guidelines_tsusoku/)
